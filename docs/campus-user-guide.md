# 研究室外の学内利用者向け GPU利用マニュアル

研究室外のゼミ生などが、学内ネットワークから研究室のGPUサーバーを利用するための手順です。申請、SSH鍵の準備、管理者による登録、PCの設定、動作確認の順に進めます。

## 1. 利用対象と接続方法

| 利用者 | 利用する接続名 | AWSの準備 |
| --- | --- | --- |
| 研究室外の学内利用者・ゼミ生 | `-campus` | 不要。AWSアカウント発行・AWS CLI・SSOログインは行いません |
| 研究室内の利用者 | `-lan`・`-campus`・`-ssm` | `-ssm`を使う場合だけ必要 |

研究室内の `-lan` は接続先への直接通信が可能なネットワーク、`-campus` は学内踏み台へ到達できるネットワーク、`-ssm` はAWS経由で接続する場合に使います。いずれも承認されたサーバー・権限の範囲で利用します。

[全体構成と接続経路の比較](system-overview.md)も参照してください。本書で使用する経路は次のとおりです。

```text
自分のPC → 学内踏み台 → 常駐リバーストンネル → Quadra → 許可されたGPUサーバー
```

学内踏み台は `www.ic.kanazawa-it.ac.jp`、ユーザー名は中継専用の `campus-relay` です。本人の公開鍵で認証し、QuadraのSSH入口への通信中継だけを利用します。踏み台でのシェルへのログインやコマンド実行は禁止されています。学内の別の部屋やprivateネットワークでも、このホストのSSHへ到達できることが条件です。「学内にいる」だけでは通信が保証されません。Quadraと踏み台の間のトンネルは管理者が維持します。利用者がトンネルを起動する必要はありません。

トンネルはQuadraから踏み台へ張られ、踏み台内部の `127.0.0.1:2222` をQuadraのSSHへ転送します。`127.0.0.1` はここでは自分のPCではなく踏み台から見た宛先です。仕組みは[リバーストンネルの説明](system-overview.md#3--campus学内踏み台とリバーストンネル)を参照してください。

## 2. 申請する

管理者は中沢実（[nakazawa@infor.kanazawa-it.ac.jp](mailto:nakazawa@infor.kanazawa-it.ac.jp)）です。申請は、[申請フォーム](https://forms.cloud.microsoft/pages/responsepage.aspx?id=Xbxum3IjmUClZWULy8MnT6rI0kF_K9lEhfaBpChXa5JUNzlWOE05NlQxWVFDNlExMVhRV09BT05YSS4u&route=shorturl)，もしくは，管理者へ大学のメールアドレスから申請内容を送ってください。AWS情報は取得せず、「研究室外・学内利用のみ（-campus）、AWS利用なし」と明記します。

| 申請内容 | 記載すること |
| --- | --- |
| 本人・所属 | 氏名、学籍番号、所属学科・研究室・ゼミ、指導教員 |
| 連絡先 | 大学のメールアドレス |
| 利用区分 | 研究室外・学内利用のみ（-campus）、AWS利用なし |
| 利用目的・期間 | 用途、開始日、終了予定日 |
| 接続元 | PCのOS、利用予定の学内ネットワーク・場所 |
| 希望アカウント | 希望するFreeIPAユーザー名。最終的な名前は管理者が通知 |
| 必要な資源 | GPUサーバー、共有領域、必要ならDocker利用の理由 |
| SSH公開鍵・指紋 | 次節で作成する `.pub` の1行全体と `SHA256:...` |

鍵が未作成なら次節で準備してから申請を完了してください。初回相談時には鍵を後から提出する旨を伝えます。秘密鍵、鍵のパスフレーズ、アカウントのパスワードは提出しません。

## 3. 自分のPCでSSH鍵を準備する

[SSH鍵の作成とFreeIPAアカウントへの登録](ssh-key-setup.md)を順番に進めてください。希望するFreeIPAユーザー名は申請項目であり、鍵のコメントに書くだけでは登録されません。管理者が確定したアカウントへ公開鍵を登録します。

自分のPCで鍵を作成し、公開鍵（`.pub`）の1行全体と指紋を提出します。秘密鍵はPCに保管します。既存鍵を上書きせず、すでに提出済みなら作り直しません。本経路では踏み台・FreeIPA両方への登録完了を待って、次へ進みます。

## 4. 管理者から利用開始の通知を受け取る

申請しただけでは接続できません。以下が通知され、公開鍵の登録が完了してから進みます。

| 通知内容 | 用途 |
| --- | --- |
| 踏み台の中継利用許可 | `campus-jump` のユーザー名は `campus-relay` |
| 本人のFreeIPAユーザー名 | QuadraとGPUにログインする名前 |
| 公開鍵の登録完了・指紋 | 踏み台とFreeIPAの両方で本人の鍵が登録されたことを確認 |
| 許可されたGPU・利用期限 | 接続先と利用範囲 |
| 許可された共有領域・グループ | 保存先と利用権限 |
| 踏み台・Quadra・対象GPUのホスト鍵指紋 | 初回接続時にサーバーが正しいことを確認 |

踏み台の `campus-relay` と本人のFreeIPAアカウントは別のものです。踏み台ユーザー名は共通でも、鍵は利用者ごとに登録します。Quadra・GPUには本人のFreeIPAユーザー名を設定し、他人の研究室アカウントや秘密鍵を共有しません。既存のSSH configで `campus-jump` の `User` が `pi` の場合は、`campus-relay` へ変更してください。

管理者は研究室外の学内利用者にAWSアカウント・SSM権限を発行しません。踏み台で本人の公開鍵とQuadraのトンネル入口への転送許可、Quadra・GPUで本人のログイン権限を設定します。利用者が踏み台上の設定や常駐サービスを変更する必要はありません。

## 5. 自分のPCのSSH設定を作る

[学内用SSH設定例](../config/ssh_config.campus.example)の冒頭コメントに従って、自分のPCのSSH設定へ取り込んでください。保存先、本人用に置き換える値、必須の中継ブロック、OSごとの注意点はこのファイルに記載しています。許可されたGPUだけを設定します。

## 6. 順番に接続を確認する

以下はすべて**自分のPC**で実行します。RTX5090は例です。許可されたGPUの接続名へ置き換えてください。

### 6.1 設定の読み込み

```bash
ssh -G campus-jump
ssh -G quadra-campus
ssh -G rtx5090-campus
ssh -G rtx-a6000x2-campus
ssh -G aisawa-campus
ssh -G rtx-6000ada-campus
ssh -G rtx4090-campus
```

出力されたユーザー名・鍵・接続経路が、管理者の通知と[学内用SSH設定例](../config/ssh_config.campus.example)に沿っていることを確認します。この操作だけでは実接続は確認できません。

### 6.2 Quadraへの接続

```bash
ssh quadra-campus 'hostname -f; whoami'
```

初回のホスト鍵確認では、表示された指紋を管理者からの通知と照合し、一致した場合に受け入れます。踏み台・Quadraそれぞれで確認が出ることがあります。Quadraは `192.168.73.98` の別名で照合されます。不一致や鍵変更警告は管理者へ連絡し、確認せず削除・登録し直すことは避けてください。

期待する出力は `quadra.i2lab.test` と **自分のFreeIPAユーザー名**です。踏み台の `campus-relay` は中継専用なので、`ssh campus-jump 'whoami'` は許可されません。接続確認は上記のようにQuadraを宛先にして行います。

### 6.3 GPUへの接続と認識

```bash
ssh rtx5090-campus 'hostname -f; whoami; id; nvidia-smi'
```

| 接続名 | 期待するホスト名 |
| --- | --- |
| `rtx-a6000x2-campus` | `a6000.i2lab.test` |
| `aisawa-campus` | `aisawaminori.i2lab.test` |
| `rtx-6000ada-campus` | `rtx6000ada.i2lab.test` |
| `rtx4090-campus` | `rtx4090.i2lab.test` |
| `rtx5090-campus` | `rtx5090.i2lab.test` |

本人のユーザー名、承認されたグループ、対象GPUの情報が表示されれば基本確認は成功です。`nvidia-smi` はGPU・ドライバーの認識確認です。PyTorchなど個別の研究環境で計算ができるかは、その環境の導入後に別途確認します。

パスフレーズは**自分の秘密鍵を開くための入力**で、踏み台のパスワードとは別です。鍵をエージェントへ読み込んでいる場合は入力を省けます。macOS・Ubuntuでエージェントが使える場合は `ssh-add ~/.ssh/id_ed25519_i2lab` を実行します。エージェントが利用できなければ、まず通常の接続でパスフレーズを入力して確認してください。パスフレーズをなくすために鍵を作り直す必要はありません。

### 6.4 許可された保存先の確認

GPUへ対話ログインします。

```bash
ssh rtx5090-campus
```

以下は**接続したGPU上**で実行します。

```bash
pwd
id
```

管理者から `/mnt/nfs-shared/labusers` の利用を許可された場合だけ、次を実行します。他の共有領域なら通知されたパスへ変更します。

```bash
cd /mnt/nfs-shared/labusers
check_file=$(mktemp ./campus-check.XXXXXXXX) && {
    printf 'campus access check\n' > "$check_file"
    cat "$check_file"
    stat -c '%U:%G %a %n' "$check_file"
    rm -- "$check_file"
}
```

`campus access check` が読み出せ、所有者が本人・グループが管理者の指定どおりであることを確認します。試験ファイルだけを削除します。共有領域の親ディレクトリは一覧できない場合があるため、通知されたパスを直接指定します。権限エラーをsudoやchmodで回避せず、管理者へ連絡してください。

Dockerを許可されている場合は、[Docker利用ガイド](docker-user-guide.md)に従い、`docker version` と `docker ps` で利用可否を確認します。研究用コンテナの準備・GPU確認・データ保存も同ガイドを参照してください。

確認後は `exit` で自分のPCへ戻ります。

### 6.5 VS Code（利用する人のみ）

VS CodeとMicrosoftのRemote - SSH拡張を導入します。`Remote-SSH: Connect to Host...` から承認された `-campus` 接続名を選び、接続先OSはLinuxを指定します。リモートのターミナルで `hostname -f` と `whoami` を実行し、端末での試験と同じ結果になることを確認します。最初に通常のSSH接続を確認してから進めてください。

## 7. 利用開始の確認表

- [ ] 申請し、利用許可と終了予定日を受け取った
- [ ] 踏み台の `campus-relay` の利用許可、本人のFreeIPAアカウント、両方への本人の公開鍵登録を確認した
- [ ] ホスト鍵指紋を確認してQuadraへ接続できた
- [ ] 許可されたGPUへ本人のアカウントで接続できた
- [ ] `nvidia-smi` でGPUが表示された
- [ ] 共有領域を利用する場合、本人の試験ファイルの作成・読出し・削除を確認した
- [ ] Docker・VS Codeを利用する場合、それぞれの動作を確認した

管理者には、確認日、接続元ネットワーク、OS、接続名、`hostname -f`・`whoami` の結果、未完了の項目を報告します。登録済み利用者の成功例だけで、新しい利用者も利用可能になったと判断しないでください。

## 8. 困ったとき・利用終了

| 状況 | 対応 |
| --- | --- |
| `Could not resolve hostname ...-campus` | configの保存先・拡張子・Host名を確認 |
| 踏み台でタイムアウト | 接続元ネットワーク・発生時刻を管理者へ報告 |
| 踏み台のパスワードを求められる | 踏み台ユーザー名・IdentityFile・踏み台への公開鍵登録を確認 |
| `Permission denied (publickey)` | 拒否されたホスト名・ユーザー名、本人の公開鍵指紋を管理者へ連絡 |
| `127.0.0.1:2222` への接続拒否 | 管理者へトンネルの稼働確認を依頼 |
| `administratively prohibited` | 管理者へ踏み台またはQuadraの転送許可の確認を依頼 |
| Quadraへ接続できるがGPUで失敗 | 接続名と利用許可を確認し、管理者へ連絡 |
| `nvidia-smi` が失敗 | ホスト名とエラーを管理者へ連絡。利用者がドライバーを再インストールしない |
| VS Codeのみ失敗 | 通常のSSHで再確認し、Remote-SSHのログを確認 |

必要なら自分のPCで `ssh -v rtx5090-campus` を実行し、エラー付近のログを管理者へ送ります。秘密鍵・パスワード・パスフレーズ・研究データは送らないでください。

終了・延長は管理者へ連絡します。端末紛失や鍵漏えいが疑われる場合も直ちに連絡し、管理者が踏み台とFreeIPA両方の登録・権限を見直します。共有データは引継ぎを確認して扱い、他人のデータを削除しません。

研究室内のSSM利用は[SSM利用者ガイド](remote-access-user-guide.md)を参照してください。踏み台・トンネルの運用は管理者へ依頼します。
